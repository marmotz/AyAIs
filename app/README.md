# Electron Main Process Architecture

## Directory Structure

```
app/
├── main.ts                    # Entry point - minimal bootstrap
├── bootstrap/                 # Application initialization
│   ├── application.ts        # Main application orchestrator
│   ├── app-initializer.ts   # App initialization logic
│   └── app-listeners.ts     # Electron event listeners
├── config/                    # Configuration files
│   └── default-configuration.ts
├── electron/                  # Electron-specific files
│   └── preload.ts            # Preload script for contextBridge
├── services/                  # Business logic services
│   ├── app-state.service.ts  # Global application state management
│   ├── auto-updater.service.ts
│   ├── config-manager.service.ts
│   ├── debug-logger.service.ts
│   ├── icon.service.ts       # Icon utilities
│   ├── shortcut-manager.service.ts
│   ├── startup-manager.service.ts
│   ├── tray-manager.service.ts
│   └── window-manager.service.ts
├── handlers/                  # IPC communication handlers
│   ├── index.ts              # Main handler registry
│   ├── config-ipc-handlers.ts
│   ├── debug-ipc-handlers.ts
│   ├── shortcut-ipc-handlers.ts
│   ├── update-ipc-handlers.ts
│   └── window-ipc-handlers.ts
├── icon.png                   # Application icon
├── tsconfig.json             # TypeScript configuration
└── package.json              # Dependencies and scripts
```

## File Organization

### Root Level (`app/`)

- **main.ts**: Minimal entry point - only bootstraps the application
- **icon.png**: Application icon
- **tsconfig.json**: TypeScript configuration for main process
- **package.json**: Node.js dependencies and build scripts

### Bootstrap (`app/bootstrap/`)

- **application.ts**: Main orchestrator - creates and wires all services
- **app-initializer.ts**: Application initialization logic (ready event)
- **app-listeners.ts**: Electron event listeners (before-quit, activate, etc.)

### Config (`app/config/`)

- Configuration constants and default values
- Shared across multiple services

### Electron (`app/electron/`)

- Electron process-specific files
- `preload.ts`: Bridge between main and renderer processes

### Services (`app/services/`)

Core business logic services, each with a single responsibility:

- **app-state.service.ts**: Global application state management
- **auto-updater.service.ts**: Auto-update functionality
- **config-manager.service.ts**: Configuration persistence and retrieval
- **debug-logger.service.ts**: Debug logging utilities
- **icon.service.ts**: Icon path resolution utilities
- **shortcut-manager.service.ts**: Global keyboard shortcuts
- **startup-manager.service.ts**: Launch on startup management
- **tray-manager.service.ts**: System tray icon and menu
- **window-manager.service.ts**: Browser window creation and management

### Handlers (`app/handlers/`)

IPC communication handlers organized by domain:

- **index.ts**: Main registry that sets up all IPC handlers
- **config-ipc-handlers.ts**: Configuration management IPC
- **debug-ipc-handlers.ts**: Debug logging IPC
- **shortcut-ipc-handlers.ts**: Shortcut management IPC
- **update-ipc-handlers.ts**: Auto-update IPC
- **window-ipc-handlers.ts**: Window control IPC

Each handler file:

- Bridges between renderer process and services
- Implements IPC channels for a specific domain
- Has corresponding unit tests (`*.spec.ts`)

## Testing

All services, handlers, and bootstrap modules have unit tests:

- Test files follow the naming pattern: `*.spec.ts`
- Located alongside implementation files
- Run with Vitest test framework
- Use `npm test` to run all tests
- Use `npm run test:watch` for development mode

## Build Process

1. **Development**:
   - Electron main process TypeScript is compiled on-the-fly using Vite
   - Angular dev server runs on port 4213
   - Hot reload enabled for both main and renderer processes

2. **Production**:
   - Angular builds to `dist/`
   - Electron main process TypeScript compiles to `out/` (Vite output)
   - Electron Builder packages everything together
   - The `main` entry point in `app/package.json` points to `out/main.js`

3. **Output Directories**:
   - `dist/`: Angular application (renderer process)
   - `out/`: Electron main process (generated by Vite)

## Principles

1. **Single Responsibility**: Each file/service has one clear purpose
2. **Separation of Concerns**: Business logic separated from IPC handling and initialization
3. **Testability**: All services and handlers have unit tests
4. **Maintainability**: Easy to locate and modify specific functionality
5. **Scalability**: Simple to add new services or features
6. **Clean Architecture**: Organized by domain (config, debug, shortcut, update, window)
7. **Minimal Entry Point**: `main.ts` only bootstraps the application

## Architecture Flow

1. **main.ts** → Calls `bootstrapApplication()`
2. **application.ts** → Creates all services → Registers event listeners
3. **app.on('ready')** → Calls `initializeApp()`
4. **app-initializer.ts** → Initializes app, creates window, sets up services
5. **app-listeners.ts** → Handles all Electron lifecycle events
6. **handlers/index.ts** → Sets up all IPC handlers
7. Individual handlers → Bridge renderer process to services
